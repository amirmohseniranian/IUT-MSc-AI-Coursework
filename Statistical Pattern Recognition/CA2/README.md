# Statistical Pattern Recognition — Computer Assignment #2

## Overview

This repository provides a reproducible implementation of a Statistical Pattern Recognition assignment covering two classical distance-based classifiers:

* **k-nearest neighbours (kNN)** for $k \in {1,2,3}$.
* **Minimum Mean Distance (MMD)**, which assigns a sample to the class whose training-set mean is closest in Euclidean distance.

The implementation evaluates these classifiers using the protocols defined in the supplied source file:

* **Iris** and **Liquid**: leave-one-out evaluation.
* **Normal**: evaluation on a fixed training/testing split.

The implementation also documents an important data-availability constraint: the assignment materials refer to databases from Computer Assignment 1.2, but the original database files and descriptions were not supplied. The project therefore uses explicit, reproducible substitutes rather than claiming to reproduce unavailable data:

* **Iris**: the UCI Iris dataset.
* **Liquid proxy**: the UCI Wine dataset, used only as a transparent tabular classification proxy.
* **Normal**: a deterministic two-class Gaussian benchmark generated by the code with seed `42`.

The implementation uses Euclidean distance on the original feature scales. It does **not** apply feature scaling, hyperparameter tuning, or alternative classifiers, because those changes would alter the requested methodology.

## Scientific Background

### k-Nearest Neighbours

For an input vector $x \in \mathbb{R}^d$, the implementation computes Euclidean distances to all training samples:

$$
d(x,x_i) = \sqrt{\sum_{j=1}^{d}(x_j-x_{ij})^2}.
$$

The $k$ training samples with the smallest distances define the neighbourhood $N_k(x)$. The predicted class is the one receiving the largest number of votes:

$$
\hat{y}(x) = \arg\max_c \sum_{x_i \in N_k(x)} \mathbf{1}\{y_i=c\}.
$$

The code evaluates exactly three neighbourhood sizes: $k=1$, $k=2$, and $k=3$.

If the vote is tied, the implementation resolves it deterministically by selecting the class of the nearest neighbour among the tied classes. This makes the prediction procedure reproducible rather than dependent on an unspecified tie rule.

### Minimum Mean Distance

For each class $c$, the training-set prototype is the arithmetic mean of its members:

$$
\mu_c = \frac{1}{n_c}\sum_{i:y_i=c}x_i,
$$

where $n_c$ is the number of training samples in class $c$. The MMD classifier predicts the class whose mean vector is closest to the test sample:

$$
\hat{y}(x) = \arg\min_c \lVert x-\mu_c\rVert_2.
$$

The implementation uses the same Euclidean norm as kNN. MMD therefore represents each class with a single prototype vector and compares the query with those prototypes.

### Leave-One-Out Evaluation

For Iris and the Liquid proxy, the implementation uses standard leave-one-out evaluation. For each sample $i$, that sample is removed from the training set before its prediction is made:

$$
\hat{y}_{-i}
=
f\left(
x_i;\,
\{(x_j,y_j):j\neq i\}
\right).
$$

The corresponding accuracy is:

$$
\operatorname{Accuracy}_{\mathrm{LOO}}
=
\frac{1}{n}
\sum_{i=1}^{n}
\mathbf{1}\{\hat{y}_{-i}=y_i\}.
$$

This protocol uses every observation once as a test case and ensures that the evaluated observation is excluded from its own training subset.

### Fixed Hold-Out Evaluation

For the Normal benchmark, the code keeps the training and test sets separate. Test labels are never used to construct the classifiers. Accuracy is computed as:

$$
\operatorname{Accuracy}_{\mathrm{test}}
=
\frac{1}{n_{\mathrm{test}}}
\sum_{i=1}^{n_{\mathrm{test}}}
\mathbf{1}\{\hat{y}_i=y_i\}.
$$

## Methodology

The pipeline is:

1. Create the output directories under `assignment2_outputs/`.
2. Download the UCI Iris and UCI Wine archives when network access is available.
3. Fall back to the corresponding scikit-learn copies if the UCI download fails.
4. Generate the Normal benchmark deterministically from two multivariate Gaussian class distributions.
5. Validate the feature matrix and label vector dimensions and reject NaN or infinite feature values.
6. Evaluate kNN with $k=1,2,3$ and MMD under the prescribed protocol for each dataset.
7. Compute accuracy and confusion matrices.
8. Save tabular results, figures, and metadata.
9. Package the generated artifacts together with the standalone Python implementation and a text README.

### Normal benchmark generation

The Normal dataset contains two classes with 60 training samples and 40 testing samples per class. The generation uses NumPy's `default_rng` with seed `42`.

The class means are:

$$
\mu_0 = (-1.5,-1.0)^T,
\qquad
\mu_1 = (1.5,1.0)^T.
$$

Both classes use the following covariance matrix:

$$
\Sigma =
\begin{pmatrix}
0.75 & 0.20 \\
0.20 & 0.75
\end{pmatrix}.
$$

The code samples each class independently for the training and testing partitions. Because the random generator seed and distribution parameters are fixed in the source, the generated benchmark is deterministic under the same software environment.

## Implementation Details

| `save_results`            | Writes result tables and classifier summaries as CSV files.                                      |
| `main`                    | Executes the complete standalone experiment and writes metadata.                                 |

### Data validation

Before classification, `_validate_xy` enforces four conditions on the feature matrix and label vector:

* `X` must be two-dimensional.
* `y` must be one-dimensional and have the same number of samples as `X`.
* The dataset must not be empty.
* `X` must contain only finite values.

This is a useful reproducibility safeguard: malformed data fail explicitly instead of producing silent downstream errors.

### Distance computation and feature scaling

The classifier implementations use the raw numerical feature scales. The code deliberately does not standardize or normalize the variables before computing Euclidean distances.

This matters because Euclidean methods are sensitive to feature magnitude, so the resulting behaviour reflects the original representation rather than a scale-invariant preprocessing pipeline.

### Evaluation artifacts

For each evaluated classifier configuration, the source writes an annotated confusion matrix at 300 DPI. Result rows include:

* `dataset`
* `evaluation_protocol`
* `classifier`
* `parameter`
* `accuracy`
* `accuracy_percent`

The implementation also records:

* the best result per dataset,
* the mean accuracy per dataset/classifier pair, and
* experiment metadata describing the seed and evaluation requirements.

## Limitations and Scientific Caveats

### 1. The original Liquid database is unavailable

The main limitation is data provenance. The source explicitly states that the databases described in Assignment 1.2 were not provided. Therefore, the Wine dataset is a **proxy**, not the original Liquid dataset. Conclusions about the original assignment's Liquid task would require the missing data.

### 2. Euclidean distance is scale-sensitive

Because no normalization or standardization is applied, features with larger numerical ranges can contribute more strongly to Euclidean distances. This is especially relevant for the multi-feature Wine proxy. The implementation follows the requested methodology rather than correcting this effect.

### 3. No model selection procedure is performed

The code evaluates only $k=1,2,3$ and MMD. It does not perform cross-validation-based hyperparameter selection, metric learning, feature selection, or systematic preprocessing comparison.

### 4. Leave-one-out evaluation is computationally repetitive

The LOO implementation rebuilds the effective training subset for every sample and recomputes distances for each prediction. This is appropriate for the assignment protocol, but it is not the most computationally efficient way to implement nearest-neighbour evaluation.

### 5. MMD is a prototype classifier

MMD represents each class by a single arithmetic mean. For a class with multimodal structure, that single mean can be inadequate even when the class is well separated under a more expressive decision rule.

### 6. Synthetic Normal data are not empirical data

The Normal benchmark is generated from explicitly chosen Gaussian parameters. Its results measure classifier behaviour under this controlled synthetic distribution and should not be interpreted as evidence about a real-world population.

### 7. No uncertainty analysis is reported

The implementation reports point accuracy and confusion matrices, but it does not compute confidence intervals, repeated trials, bootstrap uncertainty, statistical significance tests, or variance estimates for the observed accuracies.
